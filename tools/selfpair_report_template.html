Registering a bone against itself

Each talus mesh is sampled twice, one copy is rotated and translated at random, both copies get Gaussian noise, and GeoTransformer has to put them back together. No RANSAC, no fine-tuning, no ICP refinement — just the released 3DMatch weights on data they have never seen.

Figures are for the 3DMatch weights under full random SO(3) rotation — the hardest configuration tested. Recall counts a pair as registered when rotation error is under 5° and translation error under 2 mm.

Is any specimen harder than the rest?

Mean point RMSE per talus across its three trials, with the min–max range. The spread is narrow: accuracy is a property of the method here, not of individual bone shapes.

How the pairs were made

sampling
Two independent area-weighted surface samplings per mesh, so no point has a twin in the other cloud
normalize
Shared unit-sphere frame per specimen; a talus radius is ~30 mm
transform
Random rotation (≤45° Euler, or uniform SO(3)) and translation up to 0.5 normalized units
noise
Gaussian σ = 0.01 clipped at 0.05, applied to both clouds — about 0.3 mm σ, 1.5 mm max
overlap
Full; no cropping
points
20 000 per cloud for 3DMatch, 1 024 for ModelNet, matching each model's training density

Reproduce a configuration:

python tools/selfpair_eval.py --model 3dmatch \
    --rotation_mode so3 --rotation_magnitude 180 \
    --num_trials 3 --tag 3dmatch_so3180

python tools/selfpair_6dof.py     # per-axis tables
python tools/selfpair_artifact.py # this page

Runs are seeded, so the same command reproduces the same 93 pairs.
